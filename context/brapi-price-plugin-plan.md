# BRAPI Price Updater Plugin Plan

## Goal

Implement a **manual (button-triggered) price updater** integrated with Fava that:

- Fetches price history from BRAPI.
- Updates prices for **current open holdings only**.
- Writes data to a dedicated `prices/` folder structure.
- Creates/updates per-asset corporate events files.

No automatic/scheduled updates in this version.

---

## Confirmed Product Decisions

1. **Asset scope now**: only assets with current open position (`> 0` units).
2. **Ticker mapping now**: BR tickers are sent to BRAPI **as-is** (e.g., `PETR4`).
3. **Non-BR assets now**: skipped with warning in run summary.
4. **Fava UX now**: a dedicated extension page with a custom **"Update Prices"** button.
5. **Update strategy now**:
   - Incremental from last saved date,
   - request starts from ~1 week before (`overlap`) to present,
   - if overlap prices diverge, assume split/corporate-adjustment mismatch and do full history refresh.
6. **Future scope (not in this version)**: explicit "update selected ticker(s)" option.

---

## BRAPI Response Structure (validated with 7d sample)

Observed in `GET /api/quote/<TICKER>?interval=1d&range=7d&dividends=true`:

- `results[0].historicalDataPrice[]` with daily candles:
  - `date` (unix timestamp), `open`, `high`, `low`, `close`, `volume`, `adjustedClose`
- `results[0].currency` (e.g., `BRL`)
- `results[0].dividendsData.cashDividends[]`
- `results[0].dividendsData.stockDividends[]`

For Beancount price directives, `historicalDataPrice.close` will be used.

## Target File Layout

```text
prices/
  prices.bean
  <ASSET>.bean
  <ASSET>_events.bean
```

### `prices/prices.bean`

- Master include index.
- Contains one `include` per asset file and events file.
- Rebuilt every run, stable sorted order.

Example:

```beancount
; Auto-generated by BRAPI price updater
; last_update: 2026-06-15

include "BBAS3.bean"
include "BBAS3_events.bean"
include "PETR4.bean"
include "PETR4_events.bean"
```

### `prices/<ASSET>.bean`

- Header metadata comments with at least:
  - source (`BRAPI`)
  - asset ticker
  - quote currency
  - `last_update`
  - `generated_at`
- Daily Beancount `price` directives sorted by date ascending.

Example:

```beancount
; source: BRAPI
; asset: PETR4
; quote_currency: BRL
; last_update: 2026-06-15
; generated_at: 2026-06-15T14:30:00-03:00

2026-06-09 price PETR4 35.27 BRL
2026-06-10 price PETR4 35.10 BRL
```

### `prices/<ASSET>_events.bean`

- Header metadata comments.
- Populated from BRAPI `dividendsData` (if present):
  - stock events (`stockDividends`) and cash events (`cashDividends`) as custom directives/comments.
- If no events exist, keep a generated stub noting no events found.

## Fava Integration Architecture

Create a custom Fava extension module (under project root import path), exposed in `main.bean` via:

```beancount
custom "fava-extension" "plugins.price_updater"
```

Extension responsibilities:

1. Render a report page (menu entry) titled e.g. **Price Updater**.
2. Provide a button: **Update Prices**.
3. POST to extension endpoint (`update_prices`).
4. Execute updater service and return a run summary (updated assets, skipped assets, warnings, errors).

No background jobs; only manual trigger.

---

## Updater Service Design

## 1) Discover target assets (open holdings)

- Scan ledger entries and aggregate commodity units for investment asset accounts (e.g. `Assets:Investment:*`).
- Keep tickers with final balance `> 0`.
- Filter to BR-style tickers (`^[A-Z]{4}\d{1,2}$`) for this version.

## 2) Resolve request window

Per ticker:

- If no existing file data: use configured initial range.
- If existing data:
  - identify last local price date,
  - set overlap start = `last_date - 7 days`,
  - compute needed span to today and choose nearest BRAPI-supported range (`1mo`, `3mo`, `6mo`, `1y`, `2y`, `5y`, `10y`, `max`).

## 3) Detect mismatch / split-like adjustments

- Compare overlap dates that exist both locally and remotely.
- If overlap exists and values differ beyond tolerance:
  - trigger full history refresh for this ticker (configured full range; default target later can be `10y`).

## 4) Write outputs atomically

- Generate full file content in memory.
- Write with UTF-8 and deterministic ordering.
- Rebuild `prices/prices.bean` includes from generated asset set.

## 5) Return run summary

- Updated assets count/list.
- Skipped assets count/list (e.g., non-BR).
- Full-refresh assets count/list.
- Errors/warnings.

---

## Success Criteria

- Fava shows a dedicated page with **Update Prices** button.
- Clicking button updates files under `prices/`.
- `prices/prices.bean` is generated with includes for each asset and events file.
- Each asset file includes metadata + daily `price` directives.
- Each events file is generated/populated from BRAPI event payload when available.
- Incremental mode uses overlap week and escalates to full refresh on mismatch.
- No automatic update behavior introduced.

---

## Constraints / Guardrails

- Keep implementation simple and maintainable (no over-engineering).
- Use BRAPI ticker as-is for BR assets.
- Skip unsupported/non-BR tickers with clear warning output.
- Keep selected ticker feature out of this version.
- Prefer stdlib HTTP client (no new dependency required).

---

## Validation / Rollout Notes

Planned rollout flow:

2. After validation: switch to **10 years**, **all open holdings**.

These rollout knobs will be supported through extension config/runtime parameters without changing core structure.
